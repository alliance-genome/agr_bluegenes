# Configuring BlueGenes

## Environment variables

| Envvar | Description | Default |
| ------ | ----------- | ------- |
| SERVER_PORT | Port to be used by BlueGenes web server | 5000 |
| LOGGING_LEVEL | Minimum level for logging | info |
| GOOGLE_ANALYTICS | Google Analytics tracking ID | nil |
| BLUEGENES_TOOL_PATH | Directory on server where BlueGenes tools are installed | ./tools |
| BLUEGENES_DEPLOY_PATH | Custom URL path to host BlueGenes. Must start with `/` and **not** end with `/`, e.g. `/bluegenes`. If you wish to host at root, set to `nil`. | nil |
| BLUEGENES_BACKEND_SERVICE_ROOT | Override BLUEGENES_DEFAULT_SERVICE_ROOT for backend API requests (usually an internal address) | nil |
| BLUEGENES_DEFAULT_SERVICE_ROOT | Default InterMine service to run API requests against | https://www.flymine.org/flymine |
| BLUEGENES_DEFAULT_MINE_NAME | Mine name to display for default mine | FlyMine |
| BLUEGENES_DEFAULT_NAMESPACE | Namespace of the default mine | flymine |
| BLUEGENES_ADDITIONAL_MINES | Additional mines managed by this BlueGenes instance | [] |
| HIDE_REGISTRY_MINES | Disable acquiring and displaying mines from the public InterMine registry | false |

## How to configure

BlueGenes supports the many methods of specifying configuration keys provided by [Yogthos' config](https://github.com/yogthos/config#yogthosconfig). The configuration keys listed above can be specified in uppercase or lowercase, and with dashes, underscores or periods as separators.

### Configuration via `config.edn` files

Copy and paste `config/defaults/config.edn` to `config/dev/config.edn` or `config/prod/config.edn` and tweak it to match your preferences. The correct config file will be used depending on if you start BlueGenes intended for development or for production. Note that `config/defaults/config.edn` will be used when you build an uberjar or docker image, unless you use `lein with-profile prod uberjar` to bundle `config/prod/config.edn` instead.

### Analytics (optional)

For now, the only supported statistics service is [Google analytics](https://analytics.google.com/). If you wish to use this service, configure your domain and then add your Google Analytics ID using the `GOOGLE_ANALYTICS` key listed above.

### Alliance tools

`alliance-tools/` holds tools written for this fork. Run `scripts/install-alliance-tools.sh` to copy each package into `$BLUEGENES_TOOL_PATH/@alliance/<name>` (default `./tools`) and add it to `tools.edn`. Start BlueGenes once first: the tool store creates `tools.edn` and installs the official tools only when that file is missing, and the script exits with an error if it is absent. Existing `tools.edn` entries are kept, and rerunning updates the version in place. Restart BlueGenes afterwards. `alliance-tools/bluegenes-alliance-gene-link` shows a link to the gene's alliancegenome.org page on Gene report pages; add it to the report layout through the tool's `bluegenesAllianceGeneLink` name or leave it to the autogenerated layout.

#### Tool `depends`

One BlueGenes serves several mines (AllianceMine, WormMine, FlyMine, YeastMine) and offers every installed tool in each mine whose model passes the tool's `config.json`. The `depends` array lists what the model must contain. Each entry is a class name or a dotted path from a class:

```json
"depends": ["Gene.homologues.homologue", "Gene.diseaseAnnotation.qualifier"]
```

- A class name (`"Gene"`) must exist in the mine's model.
- A dotted path must resolve in the current mine's model. It follows references and collections by their referenced type and takes fields from the class and its superclasses (`ORF.homologues` resolves when `Gene` has `homologues`). A field that only a subclass of the referenced type has does not resolve.
- The tool is shown only when every entry resolves. Class presence is not enough: FlyMine has `PhenotypeAnnotation` but no `Gene.phenotypeAnnotations`, so `"Gene.phenotypeAnnotations"` hides the tool there.
- List the path of every column a query of the tool cannot work without. Optional parts must degrade at runtime: the tool receives the mine's model as `service.model.classes` and leaves out the column, tab or section whose path is missing, with a message.

The check is `bluegenes.utils/suitable-entities` (`path-in-model?` and `unmet-depends` for single entries).

#### List and report features across mines

Three features query paths that not every mine has. Each checks the paths against the model of the mine it queries (`bluegenes.mine-support`) and shows a short reason when one is missing. A model that is not loaded blocks nothing.

- Convert to orthologs (list page) needs `Gene.homologues.homologue.id` and `.organism.shortName` in the current mine.
- Send to another mine needs `Gene.id` and `Gene.organism.shortName` in the target mine. The "orthologs" mode also needs `Gene.homologues.homologue.primaryIdentifier` and `.organism.shortName` in the current mine. A target without them is listed as unavailable. Target models are loaded when a target is picked.
- "In other Alliance mines" (report page) skips a target mine whose model lacks `Organism.shortName`, `Organism.taxonId`, `Gene.id`, `Gene.primaryIdentifier`, `Gene.symbol`, `Gene.organism.shortName` or `Gene.organism.taxonId`. It leaves out the orthologs when the current mine has no `Gene.homologues.homologue.*` for them.

Gene identifiers are mapped between mines by `bluegenes.mine-ids/candidates`: AllianceMine stores CURIEs (`WB:WBGene00006759`). WormMine, FlyMine and YeastMine store bare ids for their own species (`WBGene...`, `FBgn...`, `S000...`) and CURIEs for HGNC, MGI, RGD, ZFIN and FB genes held in WormMine. The candidates are the id as given, without its prefix, and with the CURIE prefix of a bare WBGene, FBgn, S000 or ZDB-GENE id. A numeric remainder (`HGNC:11998`) is never stripped, as it would match an NCBI id of another gene.
